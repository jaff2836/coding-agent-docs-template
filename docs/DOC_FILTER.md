## 1. 범위와 원칙

- **대상:** 이 저장소가 추적하는 모든 Markdown 문서(`git ls-files '*.md'`)와 코드 주석입니다.
  - 문서: `docs/`, `locales/`, `template/`, root의 `AGENTS.md`·`CLAUDE.md`·README·CHANGELOG, `.agents/`·`.claude/` 스킬, `.cursor/BUGBOT.md`, `.omp/WATCHDOG.md`
  - 코드 주석: `scripts/`, `tests/`, `template/common/`의 주석과 docstring
- **대상 아님:** 채팅 보고·PR 본문·리뷰 prose(형식은 D-015가 맡음), 코드 동작과 식별자, 인용문과 외부 자료 원문, [TODO_ARCHIVE.md](./TODO_ARCHIVE.md)처럼 원문을 보존하는 기록
- **필터이지 스타일 가이드가 아닙니다.** 이 저장소의 표기 관례는 지적하지 않습니다: 표 상태 열과 heading의 `—`, `**항목:**` 리드인, 절 번호 참조, 원문을 유지하는 코드 식별자.
- **목적이 있으면 남깁니다.** 규칙에 걸려도 남길 이유를 한 줄로 말할 수 있으면 유지하고, 그 이유를 기각 사유로 적습니다.
- **주석 필터는 주석만 바꿉니다.** 코드, 식별자, import, 서식은 건드리지 않습니다.

## 2. 문서 규칙

- **D1 근거 없는 구체성:** 출처 없는 수치, 사례, 사용자 반응, 성능 주장. 근거를 링크하거나 확인한 범위로 줄입니다. 확인하지 못했으면 미확인이라고 씁니다.
- **D2 빈 강조어와 과장:** "중요합니다", "핵심적인", "강력한", "원활한", "robust", "seamless", "crucial" 같은 말로 무게만 더하는 문장. 무엇이 왜 중요한지 사실로 바꾸거나 지웁니다.
- **D3 예고 문구:** "다음과 같습니다", "살펴보겠습니다", "아래에서 설명합니다", "This section describes". heading이나 목록이 이미 보여 주면 지웁니다.
- **D4 반복과 재진술:** 같은 규칙을 다른 말로 두 번 쓰거나 절 끝에서 요약을 되풀이하는 것. 정본이 다른 문서에 있으면 링크만 둡니다.
- **D5 주체와 범위가 없는 문장:** 행위자 없는 피동("검토되었습니다" — 누가?), "다양한", "여러", "등"으로 범위를 흐리는 것. 주체와 대상을 밝힙니다.
- **D6 번역투(ko):** "~에 대해", "~를 통해", "~하는 것이 필요합니다", "~적인"의 반복, 이중 피동("~되어집니다"). 우리말 어순과 능동형으로 씁니다.
- **D7 대구와 격언체:** "X가 아니라 Y입니다"를 강조용으로 거듭 쓰거나, 한 줄 격언으로 문단을 맺는 것. 사실을 바로 말합니다.

## 3. 주석 규칙

- **C1 코드 되풀이:** 다음 줄이 이미 말하는 내용(`# 카운터 초기화` 위의 `count = 0`). 지웁니다.
- **C2 장식 구분선:** `# ======` 배너, 대문자 섹션 라벨. 필요하면 평범한 한 줄로 바꿉니다.
- **C3 단계 나레이션:** `# Step 1`, `# 먼저`, `# 마지막으로`. 흐름이 코드로 보이면 지웁니다. 흐름이 안 보이면 구조 문제입니다.
- **C4 빈 라벨:** `# Helper`, `# Main logic`, `# Note: important`. 구체적 사실이 없으면 지웁니다.
- **C5 모호한 TODO:** `# TODO: improve`. 무엇을 왜 할지 쓰거나 지웁니다.
- **C6 시그니처 반복:** 이름과 인자를 되풀이하기만 하는 docstring. 계약, 예외, 부작용, 이유가 없으면 줄이거나 지웁니다.
- **남길 주석:** 이유(why), 함정(gotcha), 불변조건, 결정·이슈 링크, 플랫폼 차이 설명

## 4. 적용 절차

1. **입력:** PR의 base..head diff에서 바뀐 추적 문서와 코드 주석입니다. 사용자가 파일을 지정하면 그 파일만 봅니다.
2. **후보 목록:** 번호를 붙여 규칙 ID, `파일:줄`, 원문 일부, 이유, 제안을 적습니다.
3. **판정:** 후보마다 채택이나 기각을 정합니다. 기각하면 이유를 관례, 목적 있음, 오탐 중 하나로 적습니다.
4. **수정:** 채택한 후보만 고칩니다.
5. **기록:** PR 본문에 `문서 필터: 후보 N, 채택 a, 기각 b(오탐 c)`를 남깁니다. 후보가 없으면 `후보 0`이라고 씁니다. TODO에는 시범 진행 수만 둡니다.

필터 결과는 작성자 쪽 점검입니다. 리뷰어는 필터 규칙 위반을 finding으로 만들지 않습니다([REVIEW.md](./REVIEW.md) §8의 스타일 선호).

## 5. 시범과 평가

- **기간:** 이 문서를 통합한 뒤 추적 문서나 코드 주석을 바꾸는 이 저장소의 PR 5개입니다.
- **평가 기준:**
  - 채택이 PR당 평균 1건 미만이면 효과가 작다고 보고 중단을 제안합니다.
  - 기각 가운데 오탐이 절반을 넘으면 규칙을 고친 뒤 다시 시범하거나 중단합니다.
  - 채택이 꾸준하고 오탐이 적으면 en·ko payload로 옮기는 설계를 새 항목으로 제안합니다.
- **결정:** 다섯 PR의 기록을 모아 사용자와 정합니다. 결정 전에는 locale artifact를 바꾸지 않습니다.
