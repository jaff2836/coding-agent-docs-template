## 1. Intent

### 1.1 문제

리뷰 라운드 절차와 기존 skill을 읽고 확인한 문제입니다.

- 라운드의 4단계는 commit까지인데 다음 라운드는 push를 전제합니다. `reviewers = self`일 때 push할지 정해져 있지 않습니다.
- 리뷰어가 현재 head에 결과를 남기지 못했을 때 head를 바꾸지 않고 다시 돌리는 등록 항목이 없습니다. 이 저장소 이력에는 빈 commit이 4건 있습니다. T-072의 2건은 MR !10의 리뷰 이력에서, pr-reviewer가 그 head에 결과를 남기지 못한 뒤(4회 시도 후 실패, 시간 초과) 사용자 요청으로 만든 것임을 확인했습니다. T-071의 1건도 commit 본문이 같은 사유를 적습니다(공급자 오류 HTTP 400으로 결과를 남기지 못함). T-069의 1건은 재리뷰가 아니라 push 뒤 note가 갱신되는지 확인하려는 것이었습니다(MR !3 본문).
- `reviewer_timeout` 동안 어떻게 기다릴지(확인 간격, 세션을 넘기는 기준)가 없습니다.
- 수집 규칙이 게시물의 작성 계정을 확인하게 하지 않습니다. 이 저장소의 리뷰어 표는 "서비스 계정이 쓴 note만 결과로 읽는다"를 따로 적어 보완했습니다.
- 판정 기록이 세션에만 있어 세션이 끊기면 무효 판정 근거가 사라집니다.
- 라운드를 소진하면 마지막 commit이 리뷰되지 않은 채 남는데 보고 항목에 없습니다.
- 임계값에 필요 없는 finding도 함께 고칠 수 있어 다음 라운드의 diff가 커집니다.
- `reviewers = self`에서는 수정한 주체가 같은 맥락에서 리뷰합니다.
- `review-round`·`design` 어댑터는 정본 문서가 없을 때 멈추라고 하지 않습니다. `review-round` 어댑터는 기본값을 문서와 따로 적어 과거에 여러 번 맞춰 고쳤습니다.
- `project-analysis`는 도입을 검토하려고 받은 외부 저장소에서도 검사 명령을 실행할 수 있게 하고, 분석 대상 안의 지시를 데이터로 다루라는 규칙이 본문에 없습니다. 위험 중요도(Critical~Low)와 결함 심각도(P0~P3)의 관계도 적혀 있지 않습니다.

### 1.2 기대 결과

- 라운드를 읽는 주체가 push 시점, 기다리는 방법, 결과를 남기지 못한 리뷰어의 처리, 누구의 게시물을 결과로 셀지를 문서에서 바로 찾습니다.
- 정본 문서가 없는 저장소에서 `review-round`나 `design`이 호출되면 절차를 짐작하지 않고 멈춥니다.
- 신뢰를 확인하지 못한 외부 저장소의 코드는 확인 없이 실행하지 않습니다.

### 1.3 범위와 비범위

- 범위: en·ko payload와 root 사본의 REVIEW_ROUND, `review-round`·`design`·`project-analysis` skill, `bugfix`·`refactor` skill의 안전 규칙 한 문장, DOCS_GUIDE 체크리스트 한 줄.
- 비범위: 리뷰어 표의 열 구성, 라운드 파라미터의 추가·기본값 변경, 4단계의 이름, skill의 description, version과 release note, root `design`·`review-round` 사본에 contract block을 넣는 일, TEMPLATE_GUIDE의 행동 검증 사례.

### 1.4 제약

- 위임 범위를 넓히지 않습니다. 같은 head 재실행은 사용자가 지정하는 `rereview = request`에서만 실행하고, push는 이미 위임된 non-force push의 시점을 적은 것입니다.
- 리뷰어 표의 열을 늘리지 않습니다. 적용 저장소가 이미 채운 표를 다시 짜지 않게 하기 위해서입니다. 계정은 `리뷰어` 칸에, 같은 head 재실행은 `재리뷰 요청 방법` 칸에 함께 적습니다.
- root REVIEW_ROUND는 리뷰어 표의 행 말고는 ko payload와 같아야 합니다(D-019).

아래 두 항목은 2026-11-25 사용자가 확인했습니다. 그 뒤에 더한 보완 두 가지도 같은 날 승인됐습니다(이 절 끝).

2. 판정 기록 사본의 위치 예시로 `.git/` 아래의 파일을 적었습니다. 보고에는 선택지로만 적었던 내용입니다.

2026-11-25 유지자가 `pr-reviewer`에는 같은 head 재실행 방법이 없다고 확인했습니다. 유지자는 `pr-reviewer`를 prview(유지자가 운영하는 다른 private 서비스)로 바꾼다고 했고, 같은 날 지시("prview로 등록")로 이 저장소의 리뷰어 표를 prview로 다시 등록했습니다. 슬롯은 유지자가 "C 유지"로 정했습니다. prview 쪽 문서와 MR 게시물, 이 프로젝트의 MR을 확인한 내용은 다음과 같습니다.

- prview에서 같은 head를 다시 리뷰하게 하는 방법은 유지자가 보내는 채팅 명령뿐이고 실행 주체가 쓸 수 없습니다. 그래서 같은 head 재실행에 "사용자만 실행할 수 있는 방법이면 실행하지 않고 지시 대기로 보고한다"를 더했습니다.
- 리뷰어 구성 변경은 MR !3처럼 작은 MR로 먼저 통합한 선례가 있습니다. 유지자는 이번에는 이 변경과 한 MR로 올리기로 했습니다("한 MR로").

위 두 보완은 prview를 확인한 뒤 더한 것이며, 유지자가 MR !11의 첫 리뷰 결과를 본 뒤 "승인하고 올리기"로 승인했습니다.

### 2.2 대안과 선택 이유

- **변경하지 않음(기각):** 빈 commit이 반복됐고, 계정 확인은 이 저장소만 표에 따로 적어 보완한 상태입니다.
- **리뷰어 표에 열 두 개 추가(기각):** 적용 저장소가 채운 표를 모두 다시 써야 합니다. 기존 칸에 함께 적는 쪽이 같은 정보를 담습니다.
- **같은 head 재실행을 `rereview = auto`에서도 실행(기각):** 실행 주체가 스스로 요청을 보내는 범위가 넓어집니다.
- **4단계 이름을 `commit·push`로 변경(기각):** skill description과 README, 도식이 모두 바뀝니다. 본문에 push 시점을 적는 것으로 충분합니다.

### 2.3 설계와 계약

- **REVIEW_ROUND §1:** 재리뷰 요청의 위임에 등록된 같은 head 재실행이 포함된다고 적었습니다.
- **§2.1:** `리뷰어` 칸에 게시 계정을 적게 하고, `재리뷰 요청 방법` 칸에 같은 head 재실행 방법을 함께 적게 했습니다. 적혀 있지 않으면 불가입니다.
- **§3:** 1단계에 확인 간격과 지시 대기 조건, self 리뷰를 하위 에이전트나 새 컨텍스트에 맡기는 규칙을 더했습니다. 3단계는 임계값에 필요한 것만 고치는 것을 기본으로 했습니다. 4단계에 push 시점을 적었습니다.
- **§4:** 수집에서 작성 계정을 표와 대조하게 하고, 타임아웃 앞에 같은 head 재실행 문단을 두었습니다.
- **§6·§10:** 리뷰되지 않은 head를 보고 항목에 더했습니다.
- **§7:** 판정 기록 사본을 Git이 추적하지 않는 위치에 둘 수 있게 했습니다.
- **`review-round` 어댑터:** 정본 문서가 없으면 시작하지 않습니다. 기본값은 REVIEW_ROUND §2 표를 가리키고 옮겨 적지 않습니다. fixture가 요구하는 `on_pass` 문장은 남겼습니다.
- **`design` 어댑터:** `docs/01-DESIGN.md`가 없으면 절차를 적용하지 않고 알립니다.
- **`project-analysis`:** 안전한 분석 절에 외부 저장소의 실행 확인과 지시 출처 규칙을, 위험 우선순위 절에 두 척도를 바꿔 적지 않는다는 문장을 더했습니다.
- **`bugfix`·`refactor`:** 신뢰를 확인하지 못한 외부 저장소의 지침 파일도 데이터로 읽는다는 문장을 더했습니다.

### 2.4 상위 설계에 미치는 영향

- D-020의 "빈 commit은 위임하지 않는다"는 그대로입니다. 같은 head 재실행은 빈 commit 없이 다시 돌리는 다른 수단입니다.
- D-005의 `project-analysis` 계약(명시 요청, 읽기 전용 기본, 근거 상태 구분)은 그대로이며 안전 규칙만 늘었습니다.
- 대체하는 결정은 없습니다.

### 2.5 위험·호환성·rollback

- REVIEW_ROUND는 adoption policy가 `merge`입니다. 적용 저장소는 다음 판에서 이 문구를 자기 문서에 병합해야 합니다. 리뷰어 표의 열은 바뀌지 않았습니다.
- 3단계의 기본 동작이 좁아졌습니다. 임계값에 필요 없는 finding을 함께 고치려면 사용자가 요청해야 합니다.
- 되돌리기: 이 변경이 고친 문장을 되돌립니다. 검사기와 manifest는 바뀌지 않았습니다.

### 2.6 완료 조건과 미해결 사항

- 구현 완료 조건: R-008의 세 명령이 통과합니다. 실행 결과는 작업 보고에 둡니다.
- 통합 완료 조건: MR 리뷰와 필수 CI, GitLab `main` 반영.
- 확인하지 못한 것: 바뀐 문구로 실제 라운드를 돌렸을 때의 동작. TEMPLATE_GUIDE의 행동 검증 사례에는 이 변경의 사례를 더하지 않았습니다.
