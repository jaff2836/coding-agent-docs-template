# 장기 확장 설계

> 선택형 양식입니다. 여러 변경이 공유하는 확장 계약과 단계별 완료 조건이 있을 때 사용합니다. 필요 없으면 이 파일과 들어오는 링크를 제거합니다. 이미 같은 역할의 문서가 있으면 [00-PROJECT.md](./00-PROJECT.md)에서 그 문서를 연결하며 중복 작성하지 않습니다.
>
> 설계 승인은 구현·통합·릴리스·지원 검증 완료가 아닙니다. 작업 상태는 [02-TODO.md](./02-TODO.md)와 지정한 변경별 PLAN에서 관리합니다.

## Metadata

- **Status:** Draft
- **Owner:** 프로젝트에 맞게 작성
- **Last reviewed:** YYYY-MM-DD
- **Review cadence:** 확장 범위·계약·완료 조건 변경 시
- **Parent:** 상위 설계의 경로·revision·적용 절
- **Approval:** 승인 범위와 확인 가능한 근거. 미승인이면 미승인
- **Decisions:** PROJECT §8의 관련 결정 ID

## 1. 목적과 범위

확장이 필요한 이유, 기대 결과, 비목표와 제약을 작성합니다.

## 2. 상위 설계와의 관계

| 상위 결정·절 | 유지 / 확장 / 대체 | 변경 내용과 이유 | 적용 조건 |
|---|---|---|---|
| 예시 | 유지 | 기존 계약 | 적용 조건 |

번호가 크거나 나중에 작성됐다는 이유로 상위 문서 전체를 대체하지 않습니다.

## 3. 요구사항과 설계

요구사항·검증 시나리오, 구성요소·책임·데이터 흐름, 계약, 오류 처리와 대안을 작성합니다. 현재 구현과 승인된 목표를 구분합니다.

## 4. 호환성과 전환

호환성, 마이그레이션·배포 순서, 단계별 rollback, 병행 운영과 제거 조건을 작성합니다.

## 5. 단계별 완료 조건

| 단계 ID | 범위 | 선행조건 | 완료 조건·검증 방법 | 실행 정본 |
|---|---|---|---|---|
| 예시 | 확장 단위 | 선행 단계 | 관찰 가능한 결과 | TODO 항목 또는 변경별 PLAN 링크 |

여기에는 단계 정의와 완료 조건을 둡니다. 현재 진행 상태·실행 체크박스는 실행 정본에서만 관리합니다. 승인된 단계의 구현은 새 INTENT·SPEC 없이 이 절을 참조할 수 있습니다.

## 6. 위험과 미결정

위험, 담당자, 대응, 관찰 신호와 재평가 조건을 작성합니다. 실측이 필요한 사항과 아직 합의하지 않은 설계 선택을 구분합니다.

## 7. 지원 검증 기준

구현된 기능을 지원한다고 선언하기 위한 검증 대상·환경·revision·증거 요건을 작성합니다. 실제 지원 상태는 PROJECT의 현재 상태에 근거와 함께 연결합니다. 한 환경의 성공을 다른 환경이나 revision의 근거로 재사용하지 않습니다.
